# Web ダッシュボード

起動: `bun run start` → `http://localhost:3456`（`--port` または `PORT` で変更）。実装は `src/ui/server.ts`（HTTP と SSE）、`src/ui/event-bus.ts`（状態と配信）、`src/ui/public/index.html`（試合の画面と共通の部品）、`src/ui/public/lab.js`（「学習」画面）、`src/ui/lab-routes.ts`（「学習」の API）、`src/ui/public/stats.js`・`src/ui/stats.ts`（「統計」画面と API）。

ヘッダの左で **「試合」「学習」「統計」** を切り替える（最後に開いた方を覚える）。

画面は1つの構成だけ（かんたん／詳細の切り替えはない）。「学習」「統計」を開いている間は、ヘッダの試合の流れ（準備・スタンバイ・対戦・振り返り）・準備／開始ボタン・試合の状態とスコア・ルームとモデルの欄を出さない。「学習」では代わりに学習の流れ（地図 → 学習 → 学習の LLM → 結果。学習の LLM を切っていればその段は出さない）を出す。学習の仕事が動いている間は「学習」に緑の点が付く。

試合の画面: 左にマップ（大きく）といまの判断、真ん中の上に思考ログ・下に行動ログ、右にメモだけ。上に状態と推定スコア／公式（途中）／ルーム最高／ターン／トークン、ルーム・LLM のモデルと思考の深さ（effort）・返答の上限・最大ターン・「自動で次へ」・準備／開始。変えた値は次の試合から。

「統計」の画面（読むだけ。`GET /api/stats`）:
- **ルームと試合**: 全体（試合数・一番の得点・試合中の LLM の費用・LLM が動かした手の割合・学習の採用／回数）、ルームごと（試合・最高・1ターンの得点の最高と平均（5ターン以上の試合）・全ターン・大きさ・Webマップ・当てられた得点・LLM の費用・終わり方）、試合ごと（得点（公式、無ければ推定）・1ターン・当てられた・公式と推定のずれ・終わり方・方策のモデル・LLM のモデルと思考の深さ・呼んだ回数・費用・LLM が動かした手の割合・きっかけが鳴った回数（内訳はマウスで）。方策の欄には試合中のモデルの切り替え（マウスでいつ・どのきっかけで））。全体にきっかけの 100 ターンあたりの回数。「きっかけの評価」: きっかけごとの鳴った回数・呼んだ回数・LLM の返答（目標・そのまま・モデル切替・返答なし）・呼んだ後／呼ばなかった後の 10 ターンの推定得点/ターンと試合平均（平均より低いものは赤。ルームを選ぶとそのルームだけ）。ルームの行を押すとそのルームの試合だけ、試合の行を押すと「試合の記録」で開く。「LLM が動かした手」は、前の構成では LLM が手を決めた手、今は LLM の目標で方策が動いた手と、LLM が切り替えたモデルで打った手。
- **試合の記録**: 試合の一覧（このルーム／全部）、スコア推移（ターンごと／試合ごと）、選んだ試合の見出し、ターン履歴と診断・進化レポート。
- **学習の推移**: モデルごとの小さなグラフ（学習1回ごとの、学習に使っていない地図での前→後の差 ± 標準誤差。塗り＝採用、白抜き＝見送り。点に載せると詳しく）と、学習の記録の表（`var/policy/train-log.jsonl`）。
- **モデルの特性**: モデルごとに学習したか・点/ターン・回収/ターン・勝ち・当てた・当てられた・罠（100 ターンあたり）・特性の札・測った日時。

「設定」の .env の画面: 各項目は日本語の名前（`src/settings.ts` の `label`）を大きく、変数名を小さく出し、説明は入力欄の下。はい／いいえの項目と選べる値は選択肢、空の欄には既定値を薄く出す。LLM のつなぎ方（`LLM_AUTH_MODE`）で使わない項目（説明が `api:` / `subscription:` で始まるもの）は隠す（値は残る）。めったに変えない項目（`src/settings.ts` で `advanced: true`。通信の待ち時間・送り直しの間隔・LLM に見せる量・シミュレータの並列数など）は、見出しの横の「詳しい設定も出す」を入れた時だけ出す（入れたかはブラウザが覚える。隠している数は見出しの下に出す）。`.env` に残っている使われなくなった項目（`OBSOLETE_SETTINGS`。サブエージェント・LLM を待って打つモード・古いソルバーの設定）は「使われなくなった項目」に理由つきで出し、× で消してから保存できる。Claude へのログインの案内はこの画面（LLM のつなぎ方・モデル）だけに出し、試合の画面のモデル欄には出さない。

## 「学習」画面（地図を並べて学習する。シミュレータだけで、CHaser サーバには触れない）

仕組みは [learning.md](learning.md)。仕事は同時に1つだけで、`src/sim/lab.ts` の `LearningLab` が受け持つ（試合後の学習・試合をしていない間の学習も同じ）。

1. **地図を作る**: 枚数（既定 12）と地図の種類を選ぶ。「いろいろ」は大きさ 15〜39 のランダムな地図、「ルーム N に似せる」は遊んだルーム（`var/room-profiles.json`）・地図の作り方を書いたルーム（`knowledge/sim-profiles.json`）・本物の地図があるルームから選び、そのルームの大きさ・ターン数に合わせ、保存した本物の地図（`var/maps/roomN/`。試合で全体マップが取れた時に保存）があれば半分ほどそれを少し変えて使う。作った地図を並べ、今の方策で全部を打たせる（学習前）。終わると全部の地図で同時に再生が始まる（青が自分と通った跡、紫が相手の「自分」＝同じ方策、赤が拾う・狙う相手）。各地図の上に、地図の種類（作った地図／本物の地図を変えたもの、全体マップなし）・今の得点・相手の数と勝ったか（マウスを載せると相手の種類）・当てられた得点・罠を踏んだ回数・1ターンあたりの得点。状態の欄に、相手に勝った地図の数・当てた／当てられた得点の合計（学習前→後）と、相手の種類の重み・自己対戦の相手に残っている前の自分の数（[learning.md](learning.md) の「相手と自己対戦」）。
2. **この地図で学習**: 時間（分）を決めて、並べた地図で学習する（毎世代、並べた地図から選んで候補のパラメータを打たせる）。進み具合（経過時間・世代・試合数・候補の最良）。止めると、そこまでの結果を確かめて終わる。
3. **結果**: 学習前と学習後の方策で、並べた地図を打たせ直す。学習前→学習後の平均（点/ターン）、地図ごとの前→後（良くなったら緑・悪くなったら赤）、学習に使っていない地図（確かめ用）での前→後・差±標準誤差・勝ち数、保存したか。「学習前／学習後」で再生する方を切り替える。保存は確かめ用の地図ではっきり良くなった時だけ（並べた地図だけに合わせすぎないため）。

**モデル**（地図を作るの左）: 打たせる・学習するモデル（特性ごとに別々に学習したパラメータ。[learning.md](learning.md) の「特性ごとのモデル」）。既定は試合で使うモデル。

**「地図」／「モデルとパラメータ」**（状態の欄の下で切り替える）: 「モデルとパラメータ」は、モデルごとのカード（名前・特性・説明・学習の目的・特性の札・点/ターン・回収/ターン・勝ち・当てた／当てられた・罠（100 ターンあたり）・最後に学習した時と結果）と「試合で使う」ボタン（`.env` の `POLICY_MODEL` に保存。次の試合から）、「特性を測る」（全部のモデルを同じ地図・同じ相手で打たせる）、学習するパラメータの表（行がパラメータで名前・意味・範囲（初め）、列がモデルで値と範囲の中の位置（薄い印は初めの値）。「固定」は学習で動かさない値、↑↓ は最後に採用した学習での変化）。

**学習の LLM**（「学習」の操作の行）: 入れるか（`LAB_COACH`）・モデル（`LAB_COACH_MODEL`。空なら試合の LLM と同じ）・思考の深さ（`LAB_COACH_EFFORT`。空なら試合の LLM と同じ）を選ぶ。.env に保存し、次に学習の LLM が動く時から使う。

「試合をしていない間も学習を続ける」（`TRAIN_IDLE` を .env に保存）は、試合の合間に毎回新しい地図で `TRAIN_IDLE_CHUNK_MIN` 分ずつ学習する（試合が始まると止まり、終わるとまた始まる）。学習が終わるたびに **学習の LLM**（試合中の LLM とは別。[learning.md](learning.md)）が結果を読み、評価関数・地図の作り方・学習のやり方を直す（`LAB_COACH`）。動いている間は「学習の LLM が学習環境を直しています」、終わると最後の結果（LLM の報告、直したものごとに採用／戻したと理由、記録の場所）を状態の欄に出す。

手はいつも方策（経路探索）が決める。LLM は裏で作戦（目標）を出す。

## 画面の構成

- **ヘッダ**: 状態（待機・接続中・対戦中・思考中・進化中・停止など）と現在のルーム。
- **準備 → 開始（1つのボタン。ルーム・LLM のモデルの欄と同じ行の右端。試合中は停止もここ）**: 最初は「準備」。押すとくるくる（準備中…）になり、LLM がルール・ルームの過去の試合・作戦方針を読んで最初のメモを作る（ルームには入らない。公式のバージョンも確認）。終わると同じボタンが「開始」に変わり、隣にスタンバイOK（所要時間・トークン、公式バージョンの変更があれば赤）が出る。ルーム・モデル・effort を変えると「準備」に戻る。`AGENT_PREP=false` なら最初から「開始」。
- **スクロール**: 左の列は列全体、真ん中は思考ログ・行動ログがそれぞれ、右はメモがスクロールする。スクロールバーは細く、ホバー時だけ表示。
- **試合**: ルーム選択、LLM のモデル（候補はゲートウェイの一覧から）、effort、返答の上限、最大ターン数、「試合後に自動で次へ」。開始・停止、「試合後に一時停止」。
- **スコア推移**: ターンごとの推定スコア。ターン単位と試合単位（比較）を切り替える。main の判断率と応答時間も見える。
- **いまの判断**: 現在フェーズの方策の手と理由、LLM の作戦目標・考え中か、今のモデル（試合中の LLM が切り替える）と LLM を呼ぶ時、鳴った「きっかけ」（試合中の LLM を呼ぶ条件。[architecture.md](architecture.md)）、高得点目標と最寄りの未探索点。
- **マップ**: Canvas に盤面、自機・敵（`players`。公式のプレイヤー GIF、自機は青枠・敵は赤枠、古い目撃は半透明、ID 不明の敵は仮アイコン）、軌跡、予測ルート、次の着地点、作戦目標（`planCell`）を描画。ヘッダに「更新: T<n>・Webマップ/自前マップ」。Web マップのあるルームは毎ターン取り直し（`CHASER_WEB_MAP_REFRESH`）、無いルームは観測ごとに自前マップを送る。公式タイル画像は `/assets/tiles/*.gif` を使う。
- **LLM のメモ**: 試合開始時は準備フェーズで作ったメモ。LLM が次の問い合わせへ引き継ぐメモ（`var/current/MEMO.md` と同じ）。LLM は毎回前の会話なしで呼ばれるので、何を覚えているかはここで分かる。
- **トークン**: この試合で LLM が使った合計と上限、1回あたりの入力量。詳細はマウスオーバー。
- **マップの黄色の線**: 作戦目標（なければ方策の当面の目標）までの実際の経路。
- **思考ログ**: Claude の思考、本文、ツール呼び出し、ツール結果。コンテキスト（対戦中・進化・システム）で絞り込み、折りたたみ可能。
- **行動ログ**: 1ターン1行（新しい順）。打った手（CMD1→CMD2）・推定得点の増減・誰が決めたか（方策／LLM の目標／LLM、切り替えたモデル）・理由・鳴ったきっかけ・届いた LLM の返答（何ターン目に聞いた分か・目標・モデルの切り替え）・安全手・終了。行を押すと CMD1・CMD2 の理由・推定得点・位置・きっかけの内容。「LLM・きっかけ」で、きっかけ・LLM の返答があったターンだけに絞る。同じ内容を試合の記録フォルダの `actions.log` に1ターン1行で残す（`src/agent/action-log.ts`）。
- **ターン履歴 / 診断と進化レポート**: 選んだ試合のターン表と、`diagnosis.md` / `evolution-report.md`。
- **設定ダイアログ**: 左に分類（操作・作戦方針・`.env` の分類）、右にその中身。`.env` の分類は `src/settings.ts` の `SETTING_SECTIONS`（サーバ接続・試合の進行・Webマップ・LLM のつなぎ方・方策と学習・学習の LLM・試合中の LLM・準備・試合後・その他・使われなくなった項目）。分類をまたいで編集でき、未保存の変更は分類に点で示し、まとめて「.env を保存」（再起動なしで反映）。閉じる時に未保存なら確認する。操作は「選択ルームのマップを取得」（`/api/action/preview-map`）・「方策を確かめる」（`/api/action/verify-policy`）・「モデル一覧を再取得」（`/api/models`）。最後に開いた分類を覚える。

## REST API

| メソッド・パス | 内容 |
| :--- | :--- |
| `GET /` | 画面（`index.html`） |
| `GET /assets/*` | `assets/` 配下の静的ファイル（パストラバーサルは 403） |
| `GET /api/state` | 現在の `UiDashboardState`（ルーム別成績を含む） |
| `GET /api/models` | ゲートウェイのモデル一覧と effort 候補 |
| `GET /api/runs` | ルーム別成績と直近 25 試合の要約 |
| `GET /api/runs/:id/turns` | その試合の `turns.jsonl` |
| `GET /api/runs/:id/diagnosis` | `diagnosis.md` と `evolution-report.md` |
| `POST /api/control` | 操作（下表） |
| `GET /api/claude-auth` / `POST /api/claude-auth` | サブスクリプションのログイン状態（`loggedIn`・`tokenSet`・`login.state`）と、WebUI からのログイン（`action`: `start` で URL を出す / `code` で貼ったコードを送る / `cancel` / `logout`） |
| `GET /api/env` / `POST /api/env` | `.env` の取得と保存。保存時は CHASER_ROOM と LLM_MODEL_NAME を実行中の設定にも反映 |
| `POST /api/action/preview-map` | 指定ルームの Web マップを取得し、盤面に表示 |
| `POST /api/action/verify-policy` | 方策（経路探索＋評価関数＋学習したパラメータ）のスモークテスト |
| `GET /lab.js` | 「学習」画面のスクリプト |
| `GET /api/lab` | 学習の状態（`LabState`: 動いている仕事・最後の仕事・並べた地図の組の概要と統計・空き時間の学習） |
| `GET /api/lab/rooms` | 「地図の種類」で選べるルーム（大きさ・ターン数・本物の地図の枚数・遊んだ回数） |
| `GET /api/lab/set` | 並べた地図（`set`）・各地図の始まりの盤面（`grids`）・学習前と学習後の再生用の記録（`before` / `after`。各ターンの位置・得点・手・理由・変わったマス） |
| `POST /api/lab/maps` | 地図を作って今の方策で打たせる（`n`, `room`）。すぐ返り、終わりは SSE の `lab` で届く |
| `POST /api/lab/train` | 並べた地図で学習する（`minutes`）。地図がまだ無ければ 400、ほかの仕事が動いていれば 409（空き時間の学習なら止めて代わる） |
| `POST /api/lab/stop` | 動いている仕事を止める |
| `POST /api/lab/idle` | 試合をしていない間の学習を切り替える（`enabled`。.env の `TRAIN_IDLE` に保存） |
| `POST /api/lab/coach` | 学習の LLM（`enabled`・`model`・`effort`。.env の `LAB_COACH`・`LAB_COACH_MODEL`・`LAB_COACH_EFFORT` に保存） |
| `GET /api/lab/models` | モデル（特性ごと）・学習するパラメータ・測った特性 |
| `POST /api/lab/measure` | 全部のモデルの特性を測る |
| `POST /api/lab/play-model` | 試合で使うモデル（`model`。.env の `POLICY_MODEL`） |
| `GET /stats.js` | 「統計」画面のスクリプト |
| `GET /api/stats` | 統計（`rooms`・`runs`（試合ごと。LLM の回数・費用・動かした手を含む）・`training`・`models`）。読むだけ |
| `GET /api/events` | SSE。接続直後に `state` を送り、以降は差分を流す |

### `POST /api/control` の action

| action | 挙動 |
| :--- | :--- |
| `start` | 設定を反映して試合ループを起こす |
| `stop` | 次のターン境界で止める。試合後の進化は行わない |
| `pause` | 現在の試合と進化が終わったら止める |
| `resume` | 一時停止・停止の要求を解除する |
| `update_settings` | room, model, subModel, effort, turnBudgetSec, maxTurns, autoContinue を更新する |

`start` と `update_settings` の値は次の試合から効く。進行中の試合のモデルは変わらない。

## SSE イベント

| イベント名 | データ |
| :--- | :--- |
| `state` | `UiDashboardState` 全体（接続時と状態変化時） |
| `map` | `UiMapState`（盤面、`players` 自機・敵、`planCell`、`updatedTurn`、軌跡、予測ルート） |
| `prediction` | `UiPredictionState`（フェーズ、手、理由、候補、高得点目標、ブレークポイント理由） |
| `scores` | 推定・公式・最高得点などの数値 |
| `turn` | 完了した `TurnRecord` 1 件 |
| `lab` | `LabState`（動いている仕事・最後の仕事・世代ごとの成績・並べた地図の統計・空き時間の学習の状態・学習の LLM の動きと最後の結果 `lastCoach`）。変化のたび（0.3 秒に1回まで） |
| `claude` | Claude の思考・ツールログ 1 件（`UiClaudeEvent`）。方策の失敗、試合の記録での確かめの結果、.env 更新なども同じ経路 |

接続は 15 秒ごとに keepalive を送る。

## 注意

- `Bun.serve` は hostname を指定していない。現状は全インターフェースで待ち受ける（`agent/SELF_CHECK.md` の「127.0.0.1 のみ」とは一致しない）。外部に公開しないこと。
- `GET /api/env` は値を平文で返す（画面では `secret` の項目を伏せて表示する）。認証はない。
- `POST /api/env` は `.env` を書き換える。ローカル以外から叩けない状態で使うこと。
