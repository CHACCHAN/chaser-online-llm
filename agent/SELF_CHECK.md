# SELF_CHECK.md — 自己レビュー＆改善手順（エージェント専用）

> SETUP で変更があったとき、またはコードを改修したときに実施する。**全項目合格まで「修正 → 再チェック」を繰り返す**。終わったらこのファイルと `SETUP.md` を更新する。
> 最終更新: 2026-11-21 / v21（AGENTS.md と CLAUDE.md の分離、ハーネスへのレビュー、WebUI の準備ボタン・設定画面）

## 1. 機械チェック（全て必須）
- [ ] `bun run typecheck` エラー0
- [ ] `bun test` 全通過
- [ ] `bun run verify-solver` が ok
- [ ] ソルバーの読み込み失敗を握りつぶしていない（失敗時はログ＋UIにエラー表示）
- [ ] パスは `src/paths.ts` 経由（`import.meta.dir` からの組み立てを新たに増やしていない）

## 2. スコア整合チェック（直近の試合ログ）
- [ ] `bun agent/tools/score-model-check.ts` で `mismatches: 0`（推定と公式が完全一致）
- [ ] 差がある場合は原因を特定し `tiles.json` / コスト表を修正（例: 穴の上の静止 `gr` も −20）
- [ ] 穴の再踏破数が正しくカウントされている（0 固定になっていない）

## 3. コードレビュー観点
- [ ] 使われていないコード・機能を追加していない（呼び出し元を grep で確認）
- [ ] 1ファイル 400 行目安を超えたら分割を検討
- [ ] 同じ処理のコピペがない（CMD1/CMD2 など）
- [ ] 秘密情報（`.env` の値）をログ・UI・外部送信に出していない
- [ ] 後から変えたくなる値（URL・ポート・タイムアウト・回数・有無の切替）をコードに直書きしていない。`src/settings.ts` に1項目足し、`bun scripts/gen-env-example.ts` で `.env.example` を再生成する（`src/settings.test.ts` が漏れを検出）
- [ ] マップ: 取得は裏で行い試合を待たせない。取れない間は自作マップで、`CHASER_WEB_MAP_RETRY_TURNS` ごとに再挑戦し、取れたら全体マップ表示に切り替わる（ログの "Web map fetch failed" の回数も確認）。自機・敵マーカー（`UiMapState.players`）が出る
- [ ] WebUI を外部公開していない（devcontainer 内 localhost 利用が前提。2026-11-20 ユーザー判断で hostname 制限は不要）

## 4. 進化ループの健全性
- [ ] 0〜2ターンで終わった試合（待機切れ・接続失敗）で振り返り・最高記録更新が走っていない（`AGENT_EVOLVE_MIN_TURNS`）
- [ ] 振り返りで範囲外（ハーネス本体等）が変わっていない。戻した場合は `evolution-report.md` の `Reverted (out of scope)` に出る
- [ ] 試合後の改修で `active-solver.ts` が実際に変化したか（`evolution-report.md` の `Solver Changed`）。変化なしが2回続いたら原因調査
- [ ] メイン判断率（`turns.jsonl` の `cmd1Source/cmd2Source === "main"` の割合）が 80% 以上。作戦（`mainActions` の plan/command）とサブ依頼（`delegations`）の結果も確認。低ければ予算・effort・プロンプトを見直す
- [ ] トークン: `summary.json` の `agent.usage.totalTokens` と `turns.jsonl` の `agentTokens` / `mainInputTokens`。メインの1回あたりの入力が試合を通して一定（数千トークン）で、後半で増えていないこと。`summary.json` の `agent.finalMemo` に意味のある引き継ぎ（狙い・分かったこと）が書かれていること
- [ ] 準備フェーズ: 「準備」→スタンバイOK まで上限内に終わり、公式バージョンの変更警告が出ていない（出たら SETUP.md §4）。思考ログ `[prep]` が上限内に終わり、`var/runs/<runId>/MEMO.md` の元になる試合開始時メモにルームの特徴・過去の教訓・方針が入っている（「準備フェーズ未完了」なら上限か effort を見直す）
- [ ] `mainLatencyMs` の最大がターン予算未満、かつサーバ許容時間（`SETUP.md` §1-4）未満
- [ ] メインがソルバー手を変更したターンの得失点を確認（変更が損なら `agent/prompts/main.md` か知識を直す）
- [ ] `knowledge/` と `agent/AGENTS.md` に、実測と矛盾するルールが残っていない（例: 旧「穴なら必ず gr」ルール）
- [ ] 試合後に `agent/REVIEW.md` へレビューが追記されている（無ければ思考ログの「ハーネスへのレビュー」と `AGENT_REVIEW`）。開発前に読み、対応した項目に `[対応済み]` を付けた

## 5. 判定
- 全項目 ✅ → 合格。結果を `var/self-check/<日時>.md` に残す
- 1つでも ❌ → 修正して §1 からやり直す（同じ項目で3回失敗したら人間に相談）
